# Passo 0063 — Vincular a fonte examinada ao efeito executado

## Obrigação e limite
O piloto 0062 registra bytes executados, mas não exige identidade com uma versão previamente examinada nem localiza a declaração selecionada. Acrescentar vínculo opcional por SHA-256 de arquivo completo e evidência AST da declaração. Evitar executar uma versão diferente da esperada. Isto não conecta automaticamente busca à execução, não prova identidade de um repositório/commit nem resolve dependências externas. O recorte executável e os vereditos sort-preserve-v1 continuam iguais.

## Contrato público congelado antes da implementação
- Adicionar `ExpectedSourceSHA256 string` em domain.EffectRequest, JSON expected_source_sha256.
- CLI `effects verify --expect-sha256 HEX` opcional. Vazio significa não solicitado, exceto flag explicitamente vazia na CLI, que é argumento inválido. Valor fornecido deve ter exatamente 64 dígitos hexadecimais ASCII; maiúsculas aceitas e normalizadas para minúsculas. Rejeitar valor malformado antes de chamar o verifier. Runner também valida pedidos diretos antes de ler/executar. Pedidos antigos sem hash continuam funcionando.
- Adicionar `SourceBinding EffectSourceBinding` ao EffectReport, JSON source_binding. EffectSourceBinding contém `Status`, `ExpectedSHA256`, `ActualSHA256`, `Symbol` string (JSON status, expected_sha256, actual_sha256, symbol) e `Declaration *EffectDeclaration` (JSON declaration, null quando indisponível).
- EffectDeclaration contém `StartByte`, `EndByte`, `StartLine`, `EndLine` int e `Content`, `SHA256` string; JSON snake_case. Offsets são bytes zero-based [início,fim), linhas físicas um-based inclusivas. Trecho começa no token func e termina após o fechamento da declaração, sem comentário de documentação. Hash SHA-256 do trecho bruto, sem formatação. CRLF, Unicode e //line não podem alterar coordenadas físicas.
- SourceBinding.Status é matched se o hash esperado coincide; mismatch se diverge; not_requested se omitido. Esses estados dizem respeito apenas ao arquivo. Declaração encontrada não significa execução concluída. Se a leitura falhar, retornar erro de I/O como antes.
- Ler a fonte uma vez. Comparação, análise AST, conteúdo registrado e arquivo compilado derivam dos mesmos bytes. ActualSHA256 coincide com SourceSHA256 e execution.source_sha256; ExpectedSHA256 fica normalizado no recibo.
- Divergência: status global unknown, reason e execution.stop_reason exatamente source_identity_mismatch; zero casos completos e nenhum build/subprocesso, wrapper ou binário gerado. Registrar hash real e esperado; Declaration null. Não tratar mismatch como contraexemplo da propriedade.
- Para bytes iguais ou hash omitido, aplicar todo preflight antigo. Somente fonte aceita no recorte 0062 tem Declaration, extraída da única função exportada selecionada. Recorte rejeitado, símbolo ausente/duplicado ou parse inválido => Declaration null, sem execução, global unknown. matched jamais sobrepõe uma rejeição de recorte.
- Declaração deve ser da função pedida, não de helper/comentário/string homônimos. Mudança em helper ou em qualquer byte do arquivo invalida o hash esperado mesmo quando trecho da função é igual.
- Com hash correto, executar os mesmos casos e manter veredito antigo. Sem hash, status standalone pode ser supported_in_scope; binding not_requested deixa explícito que não se verificou identidade com evidência anterior. Não criar alegação de implementação de repositório analisada. Ajuda deve explicar hash de arquivo completo, mismatch unknown sem execução e limites existentes.
